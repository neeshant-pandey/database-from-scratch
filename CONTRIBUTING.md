# Contributing Guide

## Weekly Workflow

1. **Planning (Monday)**
   - Review last week's progress
   - Define this week's goals
   - Assign tasks to team members

2. **Implementation (Tuesday-Saturday)**
   - Work on assigned tasks
   - Document progress and learnings
   - Ask questions and help each other

3. **Review (Sunday)**
   - Code review session
   - Demo working features
   - Update documentation
   - Reflect on learnings

## Code Guidelines

- Write clear, readable code with comments
- Include unit tests for all new features
- Document your design decisions
- Follow consistent naming conventions

## Commit Messages

Use descriptive commit messages:
- `feat: add B+ tree node splitting logic`
- `docs: document storage page format`
- `test: add tests for buffer pool`
- `fix: correct off-by-one error in page allocation`

## Documentation

- Add docstrings to all functions and classes
- Update README when adding major features
- Document design decisions in `/docs/design/`
- Keep weekly task logs updated

## Learning Together

- Share interesting articles or resources
- Explain concepts to each other
- Don't hesitate to ask questions
- Celebrate small wins!

## Getting Help

If stuck:
1. Try debugging and researching first (time-boxed: 30 min)
2. Post in team chat with specific question
3. Schedule a pairing session if needed
4. Document the solution for future reference
